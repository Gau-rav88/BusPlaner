## 3. Data Cleaning Rule Implementations

### Rule E01 — Exact Duplicate Deduplication
- **Definition:** Drop records that are identical across all columns (`vehicle_id, lat, lng, speed, route_id, trip_id, timestamp, date, time`).
- **SQL Implementation:**
  ```sql
  CREATE TEMP TABLE stage_e01 AS
  SELECT DISTINCT vehicle_id, lat, lng, speed, route_id, trip_id, timestamp, date, time
  FROM raw_db.vehicle_feed;
  ```
- **Formula:** $N_{\text{dedup}} = N_{\text{raw}} - N_{\text{distinct}}$
- **Verification:** Both `scripts/ingest_gps.py` and the Colab notebook execute identical DuckDB SQL queries. Verified in `backend/tests/test_gps_cleaning.py::test_gps_cleaning_logic`.

### Rule E02 — Conflicting Duplicate Resolution
- **Definition:** Multiple records sharing the exact same `(vehicle_id, timestamp)` but differing in coordinates, speed, or route.
- **Resolution Strategy:** Rank records within each `(vehicle_id, timestamp)` group deterministically:
  ```sql
  ROW_NUMBER() OVER (
      PARTITION BY vehicle_id, timestamp
      ORDER BY speed DESC, lat, lng
  ) as conflict_rank,
  COUNT(*) OVER (
      PARTITION BY vehicle_id, timestamp
  ) as conflict_group_size
  ```
- **Action:**
  - Rank 1 records are retained (`stage_e02`).
  - Rank > 1 records are quarantined into `conflicts.parquet`.
- **Schema Alignment:**
  - In `scripts/ingest_gps.py`, quarantine records receive:
    `vehicle_id, timestamp, lat, lng, speed, route_id, trip_id, conflict_rank, conflict_group_size, quarantine_reason, service_date`.
  - In `v1` of the notebook, `quarantine_reason` and `service_date` were omitted.
  - In `v2` of the notebook, this discrepancy was corrected to match `scripts/ingest_gps.py` exactly.

### Rule E03 — Spatial Bounding Box Filter
- **Definition:** Remove coordinates outside the official National Capital Region (NCR) bus operational envelope:
  - Latitude: $[28.000000^{\circ}\text{N}, 29.200000^{\circ}\text{N}]$
  - Longitude: $[76.500000^{\circ}\text{E}, 77.800000^{\circ}\text{E}]$
  - Non-NULL coordinates only.
- **SQL Implementation:**
  ```sql
  WHERE TRY_CAST(lat AS DOUBLE) >= 28.0 AND TRY_CAST(lat AS DOUBLE) <= 29.2
    AND TRY_CAST(lng AS DOUBLE) >= 76.5 AND TRY_CAST(lng AS DOUBLE) <= 77.8
  ```
- **Quarantine Reason:** `'E03_OUT_OF_BOUNDS_COORDINATE'`.
- **Verification:** Output quarantine table `out_of_bounds.parquet` captures all records failing bounds or containing NULLs. Both implementations match.

## 4. Mathematical Accounting Closed Identity

Both pipelines enforce a strict conservation identity:
$$\Delta_{\text{accounting}} = N_{\text{raw}} - (N_{\text{clean}} + N_{\text{dedup}} + N_{\text{conflicts}} + N_{\text{oob}}) \equiv 0$$

### Formal Algebraic Proof of Conservation
1. Let $S_{\text{raw}}$ be the multi-set of all rows in `vehicle_feed`, with cardinality $|S_{\text{raw}}| = N_{\text{raw}}$.
2. Stage E01 partitions $S_{\text{raw}}$ into unique rows $S_{\text{distinct}}$ and discarded duplicates $S_{\text{dedup}}$, such that:
   $$N_{\text{raw}} = N_{\text{distinct}} + N_{\text{dedup}}$$
3. Stage E02 partitions $S_{\text{distinct}}$ by `conflict_rank`:
   - $S_{\text{e02}} = \{r \in S_{\text{distinct}} \mid \text{conflict\_rank}(r) = 1\}$
   - $S_{\text{conflicts}} = \{r \in S_{\text{distinct}} \mid \text{conflict\_rank}(r) > 1\}$
   Since `conflict_rank` is a strict 1-indexed sequence without gaps for every partition, $S_{\text{e02}} \cap S_{\text{conflicts}} = \emptyset$ and $S_{\text{e02}} \cup S_{\text{conflicts}} = S_{\text{distinct}}$.
   $$N_{\text{distinct}} = |S_{\text{e02}}| + N_{\text{conflicts}}$$
4. Stage E03 partitions $S_{\text{e02}}$ via the spatial predicate $P(r)$:
   - $S_{\text{clean}} = \{r \in S_{\text{e02}} \mid P(r) \text{ is TRUE}\}$
   - $S_{\text{oob}} = \{r \in S_{\text{e02}} \mid P(r) \text{ is FALSE or UNKNOWN}\}$
   Since $P(r)$ evaluates to a Boolean or NULL (which is filtered to $S_{\text{oob}}$), $S_{\text{clean}} \cap S_{\text{oob}} = \emptyset$ and $S_{\text{clean}} \cup S_{\text{oob}} = S_{\text{e02}}$.
   $$|S_{\text{e02}}| = N_{\text{clean}} + N_{\text{oob}}$$
5. Substituting (4) into (3), and (3) into (2):
   $$N_{\text{raw}} = (N_{\text{clean}} + N_{\text{oob}}) + N_{\text{conflicts}} + N_{\text{dedup}}$$
   $$\Delta_{\text{accounting}} = N_{\text{raw}} - (N_{\text{clean}} + N_{\text{dedup}} + N_{\text{conflicts}} + N_{\text{oob}}) = 0$$

The accounting identity is mathematically closed. Any non-zero $\Delta$ indicates data corruption or pipeline disruption and triggers an immediate runtime assertion abort.
